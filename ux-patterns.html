UX patterns reference

10 patterns with critique angles for live prototype review

1

Progressive disclosure

Show only what's needed at each step. Reduces cognitive load by hiding complexity until it's relevant.

Critique: "Is this screen asking too much upfront?"
2

Empty states as onboarding

First-time views should guide the next action, not show blank pages. Turn zero-data moments into activation opportunities.

Critique: "What does a brand new user see here?"
3

Inline validation

Catch errors at the point of input, not after submission. Reduces frustration and drop-off in multi-step flows.

Critique: "Where will users get stuck or confused?"
4

Contextual actions

Surface the right action where users need it, not buried in navigation or overflow menus.

Critique: "Can users act on this without navigating away?"
5

Sensible defaults

Pre-fill what you can predict. Reduces friction for the 80% case and lets power users override when needed.

Critique: "Are we making users decide things we already know?"
6

Feedback loops

Every action needs a visible response — loading, success, error. Users should never wonder "did that work?"

Critique: "Does the user know what happened after they clicked?"
7

Information hierarchy

Primary action and key information should dominate visually. Secondary elements recede. Nothing competes.

Critique: "What's competing for attention on this screen?"
8

Reversible actions

Let users undo instead of asking "are you sure?" Confirmation dialogs are a sign the UI doesn't trust the user.

Critique: "What's the cost of a mistake here?"
9

Social proof / trust signals

Show evidence that others have succeeded with this flow. Testimonials, usage counts, security badges reduce hesitation.

Critique: "Why should the user trust this enough to act?"
10

Clear value proposition

Users should understand "what's in it for me" within 5 seconds. If they can't, no amount of good UX saves the product.

Critique: "If I landed here cold, would I know why I should care?"
